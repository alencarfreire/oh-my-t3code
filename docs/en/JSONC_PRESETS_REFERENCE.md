# Presets and JSONC configuration reference (`oh-my-t3code`)

🌐 **English** | [Português (Brasil)](../REFERENCIA_PRESETS_JSONC.md) · [Back to README](../../README.md)

This reference documents the complete configuration format for `oh-my-t3code`: environment variables, disk file hierarchy, JSON with Comments (JSONC) syntax, schema types, exact `extends` inheritance rules, the four seed presets catalog, and how the Preset Compiler, `settings.json` Sync, and Reverse Importer operate.

## File map and environment variables

The backend resolves every filesystem path in [`AppPaths::from_env`](../../src-tauri/src/models.rs) using two optional environment variables and two fixed global skill roots:

| Source | Variable / Default path | Files and purpose |
| :--- | :--- | :--- |
| Global configuration | `$OH_MY_T3CODE_CONFIG_DIR` (`~/.config/oh-my-t3code/`) | `config.jsonc` (active global preset and `enabled` toggle) and `presets/*.jsonc` (`.json` fallback when reading) |
| T3 Code data | `$T3CODE_HOME` (`~/.t3/`) | `userdata/settings.json` (model overrides), `userdata/settings.json.bak` (automatic backup), and `userdata/statev2.sqlite` (read-only access) |
| Skill root (Skillshare) | `~/.config/skillshare/skills/` | Global skills scanned at `<skill-id>/SKILL.md` with `source: "skillshare"` |
| Skill root (Gemini) | `~/.gemini/config/skills/` | Global skills scanned at `<skill-id>/SKILL.md` with `source: "gemini"` |
| Project repository | `<workspace_root>/.t3code/preset.jsonc` | Local project override (can declare `extends` pointing to a global preset) |
| Compiled squad | `<workspace_root>/.agents/skills/<slug>-squad/` | Deterministic artifacts generated by the compiler: `SKILL.md` and `roles/<role-id>.md` |

For repository directories, `derive_project_slug` derives `<slug>` by converting the root folder name to ASCII lowercase, replacing non-alphanumeric runs with a single hyphen (`-`), trimming leading and trailing hyphens, and falling back to `"project"` if the result is empty.

When reading global presets, the engine looks for `<presets_dir>/<id>.jsonc` first and falls back to `<presets_dir>/<id>.json` if missing. Every write performed by the Preset Studio or backend always outputs `.jsonc`. During global skill scanning (`scan_global_skills`), the `skillshare` root takes precedence over `gemini` if the same `<skill-id>` exists in both directories.

## Supported JSONC syntax

The `strip_jsonc_comments` parser in [`preset_engine.rs`](../../src-tauri/src/preset_engine.rs) strips comments and trailing commas before passing the resulting JSON string to `serde_json`. You can use:

- **Line comments**: text starting with `//` through the `\n` line break
- **Block comments**: text delimited by `/* ... */` across one or multiple lines (internal newlines are preserved)
- **Trailing commas**: a comma immediately preceding `}` or `]`, even with whitespace or newlines in between
- **Protected strings**: `//`, `/* */`, and commas inside double quotes `"..."` (respecting `\"` and `\\` escapes) remain untouched

The snippet below illustrates valid JSONC features, including comments, preserved string tokens, and trailing commas:

```jsonc
{
  // Line comment allowed outside strings
  "id": "demo-utf8",
  "name": "Demo // preserved inside string /* intact */",
  /* Multi-line
     block comment */
  "roles": {
    "fixer": {
      "id": "fixer",
      "title": "Fixer", // trailing comma accepted below
    },
  },
}
```

## Complete configuration schema

All configuration objects serialize in `camelCase` (`#[serde(rename_all = "camelCase")]` in [`models.rs`](../../src-tauri/src/models.rs)) to maintain strict parity with [`src/types/ipc.ts`](../../src/types/ipc.ts).

### Identifier validation rules (`validate_safe_id`)

Every preset `id`, `extends` target, key in `roles`, and preset or role filename passes through `validate_safe_id` before any disk read or write:

- Required length between `1` and `64` characters
- Allowed characters: `[a-zA-Z0-9_-]` only (ASCII alphanumeric, hyphen, and underscore)
- Explicit path traversal guard: any occurrence of `..`, `/`, or `\` fails with `AppError::PathTraversal`

### `GlobalAppConfig` (`config.jsonc`)

Controls which global preset acts as the default for projects without a local override and whether global synchronization is active:

| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `activeGlobalPresetId` | `string` | `"default"` | Identifier of the preset in `~/.config/oh-my-t3code/presets/` used as the global default |
| `enabled` | `boolean` | `true` | Indicates whether the global preset is active to sync `defaultModelSelection` and `fallbackModelSelection` |

This `config.jsonc` example enables the built-in `default` preset globally:

```jsonc
// Oh My T3Code global configuration
{
  "activeGlobalPresetId": "default",
  "enabled": true
}
```

### `PresetConfig` (global presets and `.t3code/preset.jsonc`)

Defines the complete orchestration preset, including its fallback chain, contention policy, and role map:

| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `string` | Required | Safe preset identifier (`validate_safe_id`) |
| `name` | `string` | Required | Human-readable display name shown in the Popover and Preset Studio |
| `description` | `string` | `""` | Summary of the model strategy and preset purpose |
| `extends` | `string \| null` | `null` | ID of a parent global preset from which this file inherits and applies a patch |
| `enabled` | `boolean` | `true` | Enables or pauses the local project override |
| `topology` | `string` | `"intra-thread-squad"` | Coordination topology (`"intra-thread-squad"` or `"issue-thread-orchestrator"`) |
| `orchestrator` | `OrchestratorSelection` | `{}` | Provider instance, model, and options for the primary orchestrator agent |
| `fallbackChain` | `FallbackStep[]` | `[]` | Ordered contingency list used when quota or availability fails |
| `contention` | `ContentionPolicy` | `shared` defaults | Concurrency, test database, environment variable, and conflict-file policy |
| `roles` | `Record<string, RoleConfig>` | `{}` | Ordered map (`BTreeMap`) of specialized worker roles compiled into `roles/*.md` |
| `disabledRoles` | `string[]` | `[]` *(omitted when empty)* | Sorted, deduplicated list (tombstone) of role IDs inherited via `extends` that must be suppressed (`validate_safe_id`) |

### `OrchestratorSelection` and `FallbackStep`

Both structures specify which provider instance and model T3 Code should run, with `FallbackStep` adding an operational justification:

| Field | Type | Default | Required in | Description |
| :--- | :--- | :--- | :--- | :--- |
| `providerInstanceId` | `string` | `""` | `OrchestratorSelection`, `FallbackStep` | Instance ID in T3 Code (`"codex"`, `"antigravity"`, `"antigravity_2"`, `"claudeAgent"`, `"opencode"`, `"grok"`, or a custom instance) |
| `model` | `string` | `""` | `OrchestratorSelection`, `FallbackStep` | Model identifier (for example, `"gpt-6.1-sol"`, `"gemini-4-hydrogen"`, `"gemini-4-argon"`) |
| `options` | `Record<string, string>` | `{}` | Optional | Provider options (for example, `thinking_level` on Antigravity; `reasoningEffort` and `serviceTier` on Codex) |
| `reason` | `string` | `""` | `FallbackStep` only | Rationale rendered in the Fallback Chain section of the compiled `SKILL.md` |

Here is an Antigravity orchestrator selection paired with a first-level account failover step:

```jsonc
"orchestrator": {
  "providerInstanceId": "antigravity_2",
  "model": "gemini-4-hydrogen",
  "options": {
    "thinking_level": "high"
  }
},
"fallbackChain": [
  {
    "providerInstanceId": "antigravity",
    "model": "gemini-4-hydrogen",
    "options": { "thinking_level": "high" },
    "reason": "Level 1: Switch instance while keeping gemini-4-hydrogen"
  }
]
```

### `ContentionPolicy`

Documents repository concurrency boundaries in the compiled `SKILL.md` to prevent test database corruption or merge conflicts across subagents:

| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `singleTestDb` | `boolean` | `false` | Marks that the test suite shares a single database and requires serialized execution |
| `envVars` | `Record<string, string>` | `{}` | Required environment variables printed in the playbook (for example, `PARALLEL_WORKERS=1`) |
| `gitIgnoredBuilds` | `string[]` | `[]` | Build directories outside version control (for example, `target/`, `dist/`) |
| `conflictFiles` | `string[]` | `[]` | High-contention files requiring sequential waves (for example, `Cargo.toml`, `package.json`) |
| `defaultIsolation` | `string` | `"shared"` | Default workspace mode for subagents (`"shared"` or `"worktree"`) |

### `RoleConfig`

Each entry in `roles` defines a specialized worker and compiles into a `roles/<role-id>.md` file inside the squad skill:

| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `string` | Required | Role identifier (`validate_safe_id`) and base filename `<id>.md` |
| `title` | `string` | Required | Display title printed in the `# Role: <title> (<slug>)` header and in the `SKILL.md` table |
| `description` | `string` | `""` | Summary of the role's responsibilities |
| `whenToUse` | `string` | `""` | Trigger criteria shown in the role table of `SKILL.md` |
| `providerInstanceId` | `string` | Required | Provider instance assigned to this role |
| `model` | `string` | Required | Model assigned to this role |
| `options` | `Record<string, string>` | `{}` | Model-specific options for this role |
| `skills` | `string[]` | `[]` | Skill IDs recommended for the worker |
| `mcps` | `string[]` | `[]` | Recommended Model Context Protocol (MCP) servers (for example, `ai-memory`, `context7`) |
| `allowedPaths` | `string[]` | `[]` | Paths or globs the role is permitted to edit |
| `forbiddenPaths` | `string[]` | `[]` | Paths or boundaries the role must avoid |
| `invariants` | `string[]` | `[]` | Numbered list of mandatory rules for the role |
| `verificationCommands` | `string[]` | `[]` | Commands the worker runs before marking a task complete |

## Exact inheritance rules (`extends`)

A preset can declare `"extends": "<parent-id>"` to reuse an existing global preset and override only specific fields through `PresetPatch`.

### Depth limit and cycle detection

The recursive resolver in [`preset_engine.rs`](../../src-tauri/src/preset_engine.rs) tracks a `visited` set and a depth counter bounded by `MAX_INHERITANCE_DEPTH = 16`:

- If a preset points to itself (`extends == id`) or forms any cycle (`A -> B -> A`), resolution fails with `AppError::CycleDetected`
- If the inheritance chain reaches `depth >= 16`, resolution also returns `AppError::CycleDetected`
- Project-local presets (`.t3code/preset.jsonc`) resolve `extends` against files in the global presets directory (`~/.config/oh-my-t3code/presets/`)

### Field-by-field `merge_patch` behavior

When combining a parent preset (`base`) with a child file (`patch`), the algorithm applies type-specific merge rules:

1. **Identifier (`id`)**: uses `patch.id` if present; otherwise falls back to `fallback_id` (filename or project slug).
2. **`name` and `description`**: override the parent value only when present and non-empty after `.trim()`. If omitted, `""`, or whitespace-only, they retain the parent value.
3. **`enabled` and `topology`**: override the parent value when present in the child.
4. **Dictionaries (`orchestrator.options`, `contention.envVars`, `roles[id].options`)**: perform **key-by-key merge**. New keys are inserted and matching keys overwrite the parent, preserving all other inherited keys.
5. **Scalars in `orchestrator` and `contention`**: `providerInstanceId`, `model`, `singleTestDb`, and `defaultIsolation` replace the parent value when specified in the child.
6. **Arrays**: `fallbackChain`, `contention.gitIgnoredBuilds`, `contention.conflictFiles`, and all `RoleConfig` arrays (`skills`, `mcps`, `allowedPaths`, `forbiddenPaths`, `invariants`, `verificationCommands`) **replace the entire parent array** when specified in the child; arrays are never concatenated.
7. **`roles` map**: if `role_id` already exists in the parent, fields defined in `RolePatch` merge onto the parent role (preserving the remaining parent fields); if `role_id` does not exist in the parent, a new role is created with `id` and `title` defaulted to `role_id`.

> [!NOTE]
> **Removing and reactivating inherited roles (`disabledRoles`)**: to suppress a role inherited through `extends` (including across multi-level inheritance chains), list its `id` in `"disabledRoles": ["<role-id>"]` (validated by `validate_safe_id`, automatically deduplicated and sorted). In **Preset Studio** (`RolesMatrixTab`), deleting a role from a preset with `extends` automatically appends that ID to `disabledRoles`. To **reactivate** a removed role, either redeclare `<role-id>` under `roles` (without listing it in `disabledRoles` on the same preset) or add it again in Preset Studio — both `merge_patch` and the UI clear the tombstone from `disabledRoles`.

### Annotated `.t3code/preset.jsonc` example

This project override inherits from `hybrid-agy-codex`, keeps `explorer`, `oracle`, `designer`, and `qa-reviewer` intact, and customizes only `fixer` and the contention policy:

```jsonc
// Save at <workspace_root>/.t3code/preset.jsonc
{
  "id": "my-api-service",
  "name": "My API Service (Hybrid Custom)",
  "description": "Extends hybrid-agy-codex with single test DB and custom fixer checks.",
  "extends": "hybrid-agy-codex",
  "enabled": true,
  "orchestrator": {
    // Keeps parent model "gemini-4-hydrogen" and options, swapping only primary account
    "providerInstanceId": "antigravity",
  },
  "contention": {
    "singleTestDb": true,
    // Key-by-key merge: adds PARALLEL_WORKERS while keeping parent defaultIsolation
    "envVars": {
      "PARALLEL_WORKERS": "1",
    },
    // Replaces conflictFiles inherited from parent
    "conflictFiles": ["Cargo.toml", "package.json", "db/schema.rb"],
  },
  "roles": {
    "fixer": {
      // Keeps parent providerInstanceId ("codex") and model ("gpt-6.1-sol")
      "options": {
        // Key-by-key merge: overrides reasoningEffort, preserves serviceTier="default"
        "reasoningEffort": "xhigh",
      },
      // Arrays specified in the child replace the entire parent array for that field
      "verificationCommands": [
        "cargo check --manifest-path src-tauri/Cargo.toml",
        "cargo test --manifest-path src-tauri/Cargo.toml",
      ],
    },
  },
}
```

### Self-healing and seed migration rule

The `ensure_seed_presets` function in [`preset_engine.rs`](../../src-tauri/src/preset_engine.rs) preserves user edits inside seed presets, but automatically rewrites a seed file if it detects any of three legacy or corruption conditions:

1. Presence of the legacy camelCase key `"thinkingLevel"`.
2. UTF-8 byte sequences misdecoded as Latin-1 mojibake, detected by `looks_like_mojibake` (for example, `NÃvel`, `instÃ¢ncia`, `â↔`).
3. Invalid JSONC syntax or absence of any of the five canonical OMOS roles (`explorer`, `oracle`, `designer`, `fixer`, `qa-reviewer`).

If `~/.config/oh-my-t3code/config.jsonc` does not exist, `ensure_seed_presets` creates it with `activeGlobalPresetId: "default"` and `enabled: true`.

## How the Preset Compiler, `settings.json` Sync, and Reverse Importer work

These three modules connect declarative JSONC presets, the Markdown playbooks read by T3 Code, and the T3 Code client runtime state.

### Preset Compiler (`compiler.rs`)

Given a resolved `PresetConfig` and a `workspace_root`, the compiler in [`compiler.rs`](../../src-tauri/src/compiler.rs) validates all identifiers, verifies every output path stays inside the workspace (`ensure_within_workspace`), and generates 100% deterministic files using `BTreeMap` with zero random timestamps or UUIDs:

- **`<workspace>/.t3code/preset.jsonc`**: serializes the project preset with the header `// Oh My T3Code project preset`
- **`<workspace>/.agents/skills/<slug>-squad/SKILL.md`**: outputs YAML frontmatter (`name: <slug>-squad`, `description`) followed by the signature `# <slug> Squad — Playbook do Orquestrador (T3 Code)` and four fixed sections (`1. Preparação do Orquestrador`, `2. Papéis da Squad (roles/)`, `3. Topologia, Contenção & Isolamento`, and `4. Cadeia de Fallback`)
- **`<workspace>/.agents/skills/<slug>-squad/roles/<role-id>.md`**: emits one file per role containing `# Role: <title> (<slug>)`, `## Modelo & Instância`, `## Escopo de arquivos`, `## Skills e MCPs recomendados`, `## Regras e Invariantes do Projeto`, and `## Verificação obrigatória antes de concluir`

Both the compiler and the `settings.json` synchronizer automatically normalize the legacy `thinkingLevel` key into `thinking_level` (`normalize_options`). In addition, `t3_reader.rs` relies on the exact presence of `— Playbook do Orquestrador (T3 Code)` inside `SKILL.md` to distinguish compiler-generated squads from external manual squads.

### `settings.json` Sync (`settings_sync.rs`)

Every mutation to `~/.t3/userdata/settings.json` in [`settings_sync.rs`](../../src-tauri/src/settings_sync.rs) first saves an exact byte-for-byte backup in `~/.t3/userdata/settings.json.bak` via atomic write and preserves all unmanaged keys (`favorites`, `providerInstances`, and unknown keys):

- **Global sync (`sync_global_settings`)**: updates `defaultModelSelection` from `preset.orchestrator` and `fallbackModelSelection` from `preset.fallbackChain[0]` (when at least one fallback step exists)
- **Project sync (`sync_project_settings`)**: updates only `projectSettingsOverrides[projectId].defaultModelSelection`, preserving other keys already on that project object and overrides belonging to other projects
- **Override removal (`remove_project_settings_override`)**: deletes `projectSettingsOverrides[projectId]` after writing the `.bak` backup

Inside `settings.json`, each `ModelSelection`'s `options` object converts from `Record<string, string>` into the T3 Code array format (`[{ "id": "<key>", "value": "<value>" }]`), with `thinkingLevel` normalized to `thinking_level`.

### Reverse Importer (`importer.rs`)

When a repository already has a manual squad under `<workspace>/.agents/skills/*-squad/` without `.t3code/preset.jsonc`, the `import_project_squad` command runs `import_existing_squad` in [`importer.rs`](../../src-tauri/src/importer.rs):

1. Locates the first `*-squad` directory alphabetically inside `.agents/skills/` that contains `SKILL.md`.
2. Infers the base preset from `SKILL.md` content: selects `codex-squad` if `"codex"` appears alongside `"gpt-6"` or without `"antigravity_2"`; otherwise defaults to `agy-dual`.
3. Iterates over `roles/*.md`, validates each filename with `validate_safe_id`, and extracts title, description, `whenToUse`, instance, model, options (`thinkingLevel` normalized to `thinking_level`), skills, MCPs, `allowedPaths`, `forbiddenPaths`, `invariants`, and `verificationCommands`.
4. Detects model heuristics in the Markdown body (`gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-6-astra`, `gemini-4-argon`, `gemini-4-hydrogen`) and contention hints in `SKILL.md` (`parallel_workers=1` or `banco único` enables `singleTestDb: true`; `isolation: "worktree"` without `isolation: "shared"` sets `defaultIsolation: "worktree"`).
5. Writes `.t3code/preset.jsonc` with `id: <project_slug>` and `extends: <base_preset_id>`.
